## 3. 筛选规则

生成脚本：`scripts/library/generate_selection.py` → `selection.txt`
打包脚本：`scripts/library/build_library.py`

1. **种子清单按 LeoCAD 自身分类表达式生成。**
   直接读 `common/lc_category.cpp` 的 `DefaultCategories[]`，用与
   `lcMatchCategory()` 等价的分支实现匹配零件描述。
   这样做的原因：官方库的 `!CATEGORY` 元数据很稀疏（24985 个顶层零件里只有 6470
   个带该字段，且 `Plate` 仅 28 个），若按元数据选种子，分类树会大面积空白。
2. **排除项**：图案件（描述以 `~` 开头）、别名（`=`）、Sticker、Obsolete、Moved。
   首版只收纯色建筑零件，因此不需要 `parts/textures/`。
3. **每个分类设预算上限**（`CATEGORY_BUDGET`），大分类给更多配额，保证分类树不空。
4. **依赖闭包**：从种子出发递归解析 `1 <color> … <file>` 引用，把子件与图元一并纳入。
   闭包超过 3500 个文件即报错退出，不静默截断。
5. **不满足以下条件即构建失败**：零件数不在 500–1500、存在未识别许可、
   存在重复（大小写不敏感）路径、存在无法解析的子件引用。

## 6. 打包格式约束（不可随意改动）

`lcPiecesLibrary::OpenArchive()` 对压缩包结构有硬性要求，改错会**静默丢零件**：

| 约束 | 原因 |
|---|---|
| 根目录必须是 `ldraw/` | `OpenArchive` 对 `LDRAW/` 前缀做 `memcmp`，不匹配则跳过文件 |
| 零件在 `parts/`，子件在 `parts/s/`，图元在 `p/` | 名称大写化后按目录前缀分流 |
| 必须包含 `ldraw/ldconfig.ldr` | `LoadColors()` 优先从压缩包取颜色；缺失会静默回落内置色表 |
| 文件名大小写不敏感唯一 | 加载器把名称统一转大写后放进 `std::map` |

`tests/library/test_library_manifest.py` 的
`test_archive_layout_matches_loader_expectations` 与
`test_colour_configuration_is_packaged` 锁定这两条。

## 7. 可复现性

同一份种子清单 + 同一份官方库 → **字节完全一致**的压缩包。
实现方式：zip 条目按路径排序、时间戳固定为 `2026-01-01 00:00:00`、压缩级别固定。

## 8. 已知限制

1. **未覆盖全部常用零件。** 1160 个零件覆盖建模常用件，但用户仍会遇到未收录的
   零件。缺失时的表现：LDraw 文件照常打开，缺失零件显示为占位/无法渲染，
   不会崩溃（依赖闭包保证包内引用完整）。
2. **`Sticker` 分类为空。** 首版不收图案件与贴纸，这是范围决定，不是缺陷。
3. **未收纹理。** 因排除图案件，`parts/textures/` 不需要，压缩包不带 PNG。
4. **不含非官方库。** `ldrawunf.zip`（非官方件）不提供。
5. **不含 3D 打印/说明书专用件。** 与首发范围一致。
6. **零件描述为英文。** LDraw 官方描述语言即英文，未翻译；
   分类名与颜色名已翻译（见 `docs/ui/术语与翻译对照.md`）。
7. **库更新需重新走全流程。** 更新官方库后必须重跑
   `fetch → generate_selection → build → verify`，否则 manifest 的哈希与库版本会不一致。

## 9. 复现步骤

```bash
# 1. 取官方库（约 140 MB，缓存到仓库外）
python3 scripts/library/fetch_ldraw.py

# 2. 生成种子清单（读 common/lc_category.cpp 的分类表达式）
python3 scripts/library/generate_selection.py

# 3. 打包并写 manifest
python3 scripts/library/build_library.py

# 4. 六项校验
python3 scripts/library/verify_library.py

# 5. 单元测试
python3 -m unittest discover -s tests/library -t . -v
```

全部命令只依赖 Python 标准库，不需要 Qt，也不联网（第 1 步除外）。

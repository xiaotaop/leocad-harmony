## 2. 清单：种子与闭包

### 2.1 两个数字的区别

| 概念 | 数量 | 含义 |
|---|---:|---|
| 种子零件（selection） | **1030** | 按分类预算直接挑选的顶层零件 |
| 最终顶层零件 | **1160** | 种子 + 依赖闭包引入的顶层零件 |

依赖闭包会引入种子未列出的顶层零件：某些种子零件引用其它顶层零件
（非 `s/`、非 `p/`），这些被引用者必须一并打包，否则用户会看到缺件模型。
因此最终 1160 > 种子 1030。

### 2.2 种子来源与可复现性

种子清单由脚本从 `DefaultCategories[]` 的 31 条表达式匹配官方库零件描述生成，
不手工挑选。生成规则见 D1 文档 §4.2（7 条原则）。

复核结果：

```
清单零件数: 1030
官方库中缺失: 0            ← 1030 个全部真实存在
官方库顶层零件总数: 24985
```

**无虚构条目**：每一个 ID 都能在官方库 `ldraw/parts/` 下找到。

### 2.4 为什么 Sticker 为 0

贴纸（Sticker）是装饰件，不属于建模核心闭环。D1 §4.2 的筛选原则已排除图案件，
Sticker 分类保留在树中但为空——用户不会看到"该分类有内容却打不开"的情况，
因为空分类在面板中不发请求。

若后续需要贴纸，应在预算表中给该分类单独配额，而不是放宽全局规则。

## 3. 分类：与源码的一致性

### 3.1 单一事实来源

分类树不是本方案定义的，而是来自 `common/lc_category.cpp` 的
`DefaultCategories[]`（格式 `"Name=表达式\n"`）。方案只是**按该表挑选零件**。

逐一比对结果：

```
源码分类数: 31
selection 分类数: 31
源码有但 selection 无: []
selection 有但源码无: []
```

**完全一致**，不存在"清单里有源码分类树里没有的分类"或反之的情况。
这保证了"装进库的零件"与"面板能显示的零件"不会脱节。

### 3.2 分类表达式语义（筛选依据）

| 记号 | 含义 | 例 |
|---|---|---|
| `^Name` | 整词匹配 | `^%Brick` 匹配 "Brick 2 x 4" |
| `^%Name` | 描述开头匹配 | 同上，更严格 |
| `\|` | 或 | `^%Boat \| ^%Sail` |
| `&` | 与 | — |
| `!` | 排除 | — |

筛选脚本按与 `lcMatchCategory()` 等价的语义实现，确保与运行时判断一致。

## 4. 资源部署方案

### 4.1 归档格式约束（由加载器决定，不可自由选择）

以下四条来自 `common/lc_library.cpp` 的实际代码，不是设计选择：

| 约束 | 代码依据 | 违反后果 |
|---|---|---|
| 根目录必须 `ldraw/` | `OpenArchive()` 对 `LDRAW/` 前缀 `memcmp`（:442） | 归档被当作无效 |
| `parts/`、`parts/s/`、`p/` | 名称大写后按目录前缀分流（:1389、:1392） | 零件找不到子件 |
| 必须含 `ldraw/ldconfig.ldr` | `LoadColors()` 优先从包内提取（:305） | **静默**回落内置色表，颜色显示错误 |
| 文件名大小写不敏感唯一 | 统一转大写后入 `std::map` | 同名冲突覆盖 |

本方案归档已按此结构打包，实测：

```
文件总数: 2741
顶层零件: 1160
子件: 669
图元: 911
ldconfig: ['ldraw/ldconfig.ldr']
非 ldraw/ 前缀: []        ← 无多余根目录
```

### 4.2 部署位置：三个候选路径

`FindBundledLibraryArchive()` 按顺序探测（D3 接入）：

| 顺序 | 位置 | 适用场景 | 优先级理由 |
|---:|---|---|---|
| 1 | 应用数据目录 | 首次启动把 zip 展开到可写目录 | 可热更新、可写 |
| 2 | `applicationDirPath()` | 桌面版随包分发 | 便于开发调试 |
| 3 | `:/assets/ldraw-lite/library-lite.zip` | qrc 内嵌 | 兜底，一定存在 |

**首发建议：qrc 内嵌（第 3 项）**，理由：

- 零件库与程序同版本，不会出现"库与程序不匹配"；
- 无需首次启动解压，无写权限依赖；
- 鸿蒙沙箱下应用私有目录的写权限路径更长，内嵌规避了该问题。

**风险**：3.7 MB 进 qrc 会增大 HAP 体积，且首次访问需解压到内存。
若真机首启耗时不可接受，改为第 1 项（首启展开到数据目录），
探测顺序已预留该分支，无需改调用方。

### 4.3 与现有资源的关系

当前 `leocad.qrc` 已含：

```xml
<file>resources/library.zip</file>      <!-- 内置 128 件，保留作兜底 -->
<file>resources/ldconfig.ldr</file>     <!-- 内置色表 -->
```

新增方案**不删除**这两个文件：

- `library.zip`（128 件）作为兜底，当精简库加载失败时仍能启动；
- `resources/ldconfig.ldr` 作为磁盘侧色表备用。

### 4.4 体积对照

| 方案 | 零件数 | 归档大小 | 说明 |
|---|---:|---:|---|
| 现状 `library.zip` | 128 | 小 | 不满足 500–1500 |
| 本方案 `library-lite.zip` | **1160** | 3.7 MB | 满足需求 |
| 官方完整库 | 24985 | ~141 MB | 过大，不适合首发 |

## 5. 许可与署名

### 5.1 逐文件许可统计

| 许可 | 文件数 | 说明 |
|---|---:|---|
| CC BY 4.0 | 2547 | 主体 |
| CC BY 2.0 + 4.0（双） | 193 | 旧件，两种许可均可用 |
| **合计** | **2740** | 另有 1 个 `ldconfig.ldr` 不含 `!LICENSE` |

### 5.2 CC BY 4.0 的五项署名义务

manifest 已逐文件记录，需在发布材料中体现：

1. **指明创作者** —— 取自每个文件的 `0 Author:` 头
2. **提供作品 URL** —— `https://library.ldraw.org/`
3. **指明许可名称** —— CC BY 4.0
4. **提供许可 URL** —— `https://creativecommons.org/licenses/by/4.0/`
5. **说明是否修改** —— 是：重新打包为子集，零件内容未改

### 5.3 与 D1 阻断项的关系

D1 §5.3 的 **O-1（Qt 授权与 LeoCAD GPLv2-only 兼容性）** 仍是阻断项，
本方案不改变该结论：零件库许可（CC BY 4.0）与程序许可（GPLv2）是两件独立的事，
零件库许可清晰不影响程序侧的授权冲突。

### 6.3 关于子模型标签栏（对齐 D1 组长审核意见）

D1 结论：首版只开一个工程/文档，但**保留 MPD 内子模型的查看与切换**。

本草图据此：

| 项 | 首版处理 |
|---|---|
| 标签栏 `setMovable()` | **关闭**（组长审核意见，`lc_mainwindow.cpp:89–95` 当前为开启） |
| 标签栏 `setTabsClosable()` | **关闭**（关闭最后一个标签会进 `NewProject()`，非单工程安全交互） |
| 标签右键菜单 | **不注册**（`ModelTabContextMenuRequested`） |
| 子模型**切换** | **保留**（点击标签切换） |
| 子模型**列表对话框** | 裁剪后保留：隐藏新建/删除/重命名/导出/复制按钮，关闭拖放排序 |
| 子模型**编辑**命令 | 移除（`LC_MODEL_NEW`、内联、移动到模型等） |

即：**能看、能切，不能改结构**。

### 6.4 偏好设置裁剪

按 D1 §3.1 第 5 条原则，**不改 `.ui`**，用隐藏控件实现。隐藏项：

检查更新、POV-Ray、LGEO、Blender 集成、零件库路径、渲染相关设置。

保留：语言、主题、快捷键、显示选项、备份设置。

## 9. 复现方式

```bash
# 1. 取官方库（约 141 MB，不入库）
curl -A "leocad-harmony-library-fetch/1.0" \
     -o complete.zip https://library.ldraw.org/library/updates/complete.zip

# 2. 生成种子清单（从 DefaultCategories 匹配）
python3 scripts/library/generate_selection.py --library complete.zip

# 3. 解析依赖闭包并打包（固定时间戳，字节可复现）
python3 scripts/library/build_library.py --library complete.zip --output library-lite.zip

# 4. 六项校验
python3 scripts/library/verify_library.py --archive library-lite.zip --manifest manifest.json
```

脚本在 D3 随代码一并提交。

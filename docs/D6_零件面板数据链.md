## 2. 修的缺陷：空分类加搜索时，提示指错了方向

**症状**：Sticker 分类（按 D2 §2.6 决策本来就不收件）里输入任意搜索词，空态提示是
「没有零件匹配此搜索，请换关键词或清空搜索框」。

**问题**：换任何关键词都不会有结果，因为该分类本身是空的。提示把「分类为空」错说成
「搜索没命中」，把用户引向一个不可能成功的动作。

**根因**：判断只看搜索框是否非空：

```cpp
// 修改前
const bool Filtering = mFilterWidget && !mFilterWidget->text().isEmpty();
```

**修复**：改为「清空搜索后是否能显示内容」——这才是用户照做之后会看到的：

```cpp
const bool CategoryHasParts = View->GetListModel()->rowCount() > 0;
const bool Filtering = HasSearch && CategoryHasParts;
```

`rowCount()` 是当前分类的条目数，筛选是通过 `setRowHidden()` 实现的、不改变它，
所以这个读法无副作用、不会为了判断而改动模型。

**为什么 D4 没抓到**：D4 分开测了「空分类」和「搜索无结果」两个单独场景，都通过。
缺陷只在两者同时成立时出现——这是组合场景，不是某个函数的错。

## 3. 新增测试（9 项）

新套件 `tests/ui/d6/tst_parts_panel_chain.cpp`，工程 `d6-panel-tests.pro`，
接入两个运行脚本（套件名 `chain`）。

| 用例 | 断言 |
|---|---|
| `colourListIsPopulatedFromTheLoadedLibrary` | 颜色列表从载入的 ldconfig 建立，非空且颜色数 ≥ 300 |
| `pickingAColourReachesTheWholeChain` | 选色后：窗口索引、面板索引、按钮文字（颜色名）与色块像素**三者同时**跟上 |
| `colourChainIgnoresTheSameColour` | 重复选同一色不重发信号（避免每次颜色重载都重入主窗口） |
| `categorySelectionListsOnlyMatchingParts` | Brick 非空且**少于**全库；Sticker 为 0；切回 All Parts 复原 |
| `searchMatchesPartsThatOnlyExistInTheCuratedLibrary` | 搜到 `10172`（内置 128 件库没有）；无匹配归 0；清空复原 |
| `countAgreesWithTheRowsOnScreen` | 三种状态下计数标签都等于实际可见行数 |
| `emptyStateFollowsCategoryAndSearchTogether` | 空分类 + 有搜索词 → **不提搜索**；正常分类 + 无匹配 → 提搜索；清空后隐藏 |

**颜色为什么按「链」测**：只断言「颜色列表里选中了某个颜色」是无效的——色块高亮了、
面板和按钮没动，用户看到的仍是旧颜色。所以断言从控件一路查到色块像素。

**色块比对留 1 个通道容差**：色块由浮点值 gamma 转换后取整填充，要求完全相等等于在
测取整方式而不是测接线。

### 3.1 一处必须记录的测试自身错误

第一版有三个用例失败，**原因都在测试自己**，不是产品缺陷：

| 现象 | 真实原因 |
|---|---|
| 颜色按钮读出 `""` | `findChild<QToolButton*>()` 返回的是零件面板先构造的按钮，不是颜色按钮 |
| 搜索 `10172` 找不到 / 计数不变 | 我按构造顺序取 `Edits.at(1)` 当零件搜索框，实测 `[0]` 才是 `Filter Parts`，`[1]` 是 `Filter Categories` |

第二个尤其值得记：**面板里第一个构造的输入框是零件搜索框**，与我按命名顺序的猜测相反。
用宿主探针实测确认后改用 `objectName` 定位，不再依赖顺序。

顺手给三个控件加了 objectName：`PartsFilter`、`CategoryFilter`、
`SelectionColorButton`。这同时修掉组长在上一轮指出的问题——设备诊断原先用
「第一个有文本且带 icon 的 QToolButton」找颜色按钮，组长明确说这个选择器无法验证目标
身份。现在 `lcApplication::LogThemeWidgetState()` 直接按名字取。

## 4. 界面截图：本机无法产出，如实标记

D6 要求「提交界面截图」。本轮**没有交付截图**，原因是实测受阻，不是遗漏：

尝试写了一个离屏截图工具（`QWidget::grab()` 抓真实面板），在 `Window.show()` 之后
**段错误退出（exit 139）**。该环境是 WSL + offscreen 平台，`QOpenGLWidget` 不受支持
（日志里两处 `QOpenGLWidget is not supported on this platform.`），视图控件初始化后
崩溃发生在截图逻辑之前——连入口处的 `fprintf` 标记都没有输出。

工具已删除，没有把会崩溃的代码留在仓库里。

**结论**：界面截图应由组长按 §6.1 真机批次采集。需要覆盖的画面列在 §5。本机不声称
提供了截图证据。

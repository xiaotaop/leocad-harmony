# 成员 C D8：真机核对清单（首发界面与包内资源）

日期 2026-11-03。配套 `MEMBER_C_D8.md`。本清单只列**宿主无法定论**的项：每条给出看什么、
判据是什么、以及为什么必须真机。**本成员不做真机结论**，取证与判定按分工归组长。

## 1. 帮助菜单裁剪后的外观

本轮从菜单移除了「主页」「报告问题」两条会拉起浏览器的项（`LC_HELP_HOMEPAGE`、
`LC_HELP_BUG_REPORT`）。

- 看什么：帮助菜单是否只剩「关于 LeoCAD」；原两条是否已消失。
- 判据：**无**「主页」「报告问题」两项；帮助菜单标题与其余菜单对齐，无空白项、无灰死项。
- 为什么必须真机：鸿蒙平台菜单由 Qt 走原生路径渲染，宿主 offscreen 与本地桌面看到的不等价。
- 关联：`隐私政策.md` §2、`权限说明.md` §2.3（本轮已补依据）。

## 2. 中文菜单宽度与文字省略的真机复验（#28）

D4 真机截图里搜索筛选项出现 `Regular...ression`、`显示...零件` 省略。**代码侧已在 D7 修过**，
本项要复验的是修得对不对，不是「还没修」——这条区别很重要，本成员一度写错，已更正：

- 实现：`common/lc_partselectionwidget.cpp:1405` 按最宽项 + 样式装饰量设
  `Menu->setMinimumWidth(Widest + Overhead)`，并递归处理 `aboutToShow` 之后才填充的子菜单；
  装饰量取 `CT_MenuItem` 与 `PM_MenuButtonIndicator`/`PM_MenuPanelWidth` 的较大者。
- 断言：`tests/ui/d7/tst_localization.cpp` 的 `optionsMenuFitsItsLongestEntry` 与
  `filterSubmenuFitsItsLongestEntry` 用同一套字体度量检查子菜单宽度容得下每一项文字，
  其中显式覆盖了设备上报的两项 `正则表达式`、`零件描述`。宿主侧两条均 PASS。

- 看什么：搜索框右侧筛选子菜单与选项菜单的每一项文字是否完整可读。
- 判据：`正则表达式`、`零件描述`、`筛选零件` **不被省略号截断**；至少两种窗口宽度下成立。
- 为什么仍要真机：设备字体家族与度量不同于宿主，宿主 PASS 只证明算法自洽，不证明设备宽度足够。
  若真机仍省略，请把**实际字体家族名与测得的像素宽度**一并带回，那是修改常量或换行策略的唯一依据。
- 关联：`docs/D7_中文资源与菜单尺寸.md` §5.1（三度改写断言的过程与边界）。

## 3. 缩放 in/out 的可发现性（本轮发现，未改）

`LC_VIEW_ZOOM_IN` / `LC_VIEW_ZOOM_OUT` **不在任何菜单，也不在任何工具栏**，
仅键盘 `+` / `-` 可达（默认值来自 `lc_commands.cpp` 的 `DefaultShortcut`）。
本轮只删除了指向不存在文件的 `setIcon` 死引用，功能与快捷键未动。

- 看什么：真机键盘/外接鼠标滚轮场景下，用户是否能发现缩放功能。
- 判据由组长定：是否加入 View 菜单属范围决策（分工文档 §1.2 的等量交换规则）。
- 若决定加入：同时需要提供**真实图标文件**，
  `scripts/library/test_packaged_resources.py` 会拒绝只写引用不给文件。

## 4. 包内零件库与图标资源

- 看什么：首次启动是否直接可用内置库（1160 零件），无需任何外部路径；缩略图是否正常。
- 判据：无「could not find a compatible Parts Library」提示。
  **若该提示出现，它是缺陷信号**——库已打包在 `assets/ldraw-lite/library-lite.zip`
  （3833541 字节，sha256 `09922e82…4268c0f3`，manifest 自校验通过），
  提示文案却让用户去网站装库，在鸿蒙语境下走不通。已开 **issue #49**。
- 应用图标：64/256/512 三档已跟踪入仓；真机核对桌面与最近任务列表图标是否清晰、无默认占位。
- 关联：`HAP_ICON_DEVICE_ACCEPTANCE.md` 的图标取证方式可复用。

## 5. 字体可用性（唯一判据在真机）

Windows CI 上 `localization` 套件的**字形覆盖与文字宽度两项是 `SKIP`**（runner 的 Qt 6.8 不再自带字体），
20 passed / 2 skipped 不代表字形可用。宿主 Linux 侧为真实 PASS 且经注入验证，但那仍是宿主字体。

- 看什么：中文是否有豆腐块（.notdef）、标点是否错位。
- 判据：**无任何缺字方框**；主菜单、状态栏、面板筛选、对话框按钮四类文字均正常。
- 为什么必须真机：设备字体集合与宿主完全不同，这是字体结论的唯一来源。

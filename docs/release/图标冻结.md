## 3. 安装包和商店图标

鸿蒙打包、商店上传和 Qt 窗口分别使用以下资源。

| 用途 | 依据 | 产出的东西 |
|---|---|---|
| 应用 / Ability 图标 | [分层描述](../../app/icons/jimuligou_icon.json) | `AppScope/app.json5` 和 `module.json5` 都引用 `$media:jimuligou_icon` |
| 商店图标 | [商店 PNG](../../app/icons/jimuligou_store.png) | 1024 × 1024，纯色背景，与安装包分层图标视觉一致 |
| 启动图标 startIcon | [红砖前景 PNG](../../app/icons/jimuligou_foreground.png) | 包内 `resources/base/media/startIcon.png`，逐字节等于前景图 |
| 窗口 / 任务栏图标（最大档） | `leocad.qrc:105`，alias `resources/leocad-512.png` | 经 `common/lc_mainwindow.cpp:80-102` 组成的多尺寸 `QIcon` |

2026-10-29 的 [真机记录](../HAP_ICON_DEVICE_ACCEPTANCE.md) 对应此前使用单层 PNG 的版本。

**窗口图标是三个尺寸合成的**：`common/lc_mainwindow.cpp:87` 依次加载
`:/resources/leocad.png`（64）、`leocad-256.png`、`leocad-512.png`，把每个文件里的可用尺寸都 `addPixmap` 进同一个 `QIcon`，
让 Qt 按 `devicePixelRatio` 选档。因此**改动 64 / 256 / 512 任意一张都会改变窗口图标**，不是只有 512 重要。
参考设备 DPR≈1.9（3120×2080 面板，`docs/D10_DEVICE_ACCEPTANCE.md` 实测）。512×512 对标题栏/任务栏这个尺寸的用途足够清晰；但它只是 512 像素的位图，不是无限缩放源——若日后要更大尺寸的图标位图（例如商店宣传图放大使用），需要另出一份并更新本表，不能指望现有文件。

## 4. 决策与未闭环项

### 4.1 保留现有图标的决策

D11 用户决策：**保留现有红色积木图标，不为鸿蒙设计新图标。** 本文据此只做记录与冻结。

理由记录（供后续追溯，不作为对外表述）：D8 是界面与资源冻结点，冻结日不新增美术；

末尾两个 SVG 内容完全相同，因此哈希相同——这是上游现状，不是复制错误。

**上表两个 SVG 的字节数与 SHA-256 按 LF 行尾计算。**
`.gitattributes` 设了 `* text=auto`，所以同一个 SVG 在 Windows 检出是 CRLF（3,016 字节）、在 Linux/CI 检出是 LF（2,952 字节）。若直接对工作区字节取哈希，冻结表会在"没记录的那个平台"上失败——第一次跑 CI 时就是这么失败的。因此 `test_release_materials.py` 对文本图标先归一化为 LF 再取哈希，表格里记的就是这个平台无关的值。PNG 是二进制，不受影响。

**鸿蒙包不引用这 8 个文件。** `leocad.qrc` 只嵌入 §3 所列的三个窗口图标尺寸，
鸿蒙清单引用 `app/icons/` 下的分层资源，`leocad.pro` 的图标安装规则适用于 Linux 桌面。
（`leocad.pro` 里那段 `icons.files` 与本包的打包无关，不要因为它列出 9 个目录就以为它们都进了 HAP。）

## 7. 冻结后的变更规则

**改任何一个图标文件，必须同时改本文件对应的字节数与 SHA-256，否则视为冻结失效。**

具体规则：

1. 改尺寸、改颜色、改绘制内容——无论多小——都要重算该文件哈希并更新 §2 / §5 表格。
2. 改 64 / 256 / 512 中任意一张，还要重跑真机验证：启动画面、标题栏、任务栏三项
   （照 `docs/HAP_ICON_DEVICE_ACCEPTANCE.md` 的方法），并更新该文档里的图标原图哈希。
3. 新增或删除尺寸，要同步改 §2 表格与 `leocad.qrc`；qrc 改了却没改本文件，属于冻结失效。
4. 若更换分层图标，同步更新商店 PNG 和商店文案 §8，并检查两处视觉一致。

### 7.1 自动化覆盖到哪一步

**本节记录的是脚本存在之后的状态。** D11 定稿前这里写的是"哈希校验在仓库中不存在，冻结只是文档层面的约束"，
已随 `scripts/library/test_release_materials.py` 的加入而失效。留下这段说明，是为了让后来者知道这个保障是新增的、而非一直存在。

| 检查 | 触发时机 | 覆盖到图标吗 |
|---|---|---|
| `scripts/library/test_release_materials.py` | `continuous.yml` 的 port-policy job，每次推送 | **是**：读本文 §2 / §5 表格里的每一行，重算对应文件的字节数与 SHA-256，不一致非零退出 |
| 上表反向检查 | 同上 | **是**：`tools/icon/` 下有文件但表格里没有行，也失败——新增图标无法绕过冻结 |
| `scripts/library/test_packaged_resources.py` | 同上 | 仍然只管"文件存在"；存在与否由它守，内容是否被换由上两行守 |
| 像素尺寸与目录名是否一致（IHDR） | **无自动化** | 否。尺寸与目录名不一致时，上面的哈希检查仍会通过——它只能证明"没被改"，不能证明"尺寸对" |
| 真机图标显示 | 人工 | 否。见 `docs/HAP_ICON_DEVICE_ACCEPTANCE.md`（2026-10-29） |

**仍需人工的部分**：脚本保证的是"磁盘上的字节与表格一致"，不保证"HAP 里的图就是这个"——真正打包的那次构建是否取到了这些文件，仍需 RC0 解包核对。

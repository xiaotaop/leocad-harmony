### 1.1 关于"网络模块"与"打印模块"（两处此前表述不准，已更正）

**网络：鸿蒙包内没有 Qt Network。**

- `leocad.pro:1` 写了 `network`，但那是**历史 qmake 路径**，鸿蒙构建不走它；
- 鸿蒙构建走根 `CMakeLists.txt`：`Network` 只在 `if(NOT OHOS)` 分支被附录入
  （`CMakeLists.txt:16-17`），链接同样只在 `if(NOT OHOS)` 内（`CMakeLists.txt:93-95`）。
  因此在 OHOS 目标上既不查找也不链接 `Qt6::Network`。
- 这与打包清单未申请 `ohos.permission.INTERNET` 相互印证（见 `权限说明.md` §6）。

原表把 `Network` 列进模块清单、又标"未启用"，把"鸿蒙构建"和"qmake 历史路径"混成了一行。

**打印：鸿蒙包内确实有 PrintSupport。**

- `CMakeLists.txt:13` 与 `:90` 都包含 `PrintSupport`；`common/lc_global.h:14-15` 直接
  `#include <QPrinter>` / `<QPrintDialog>`，所以相关代码确实进了二进制。
- 但打印功能在首发版**不可达**：`LC_FILE_PRINT`/`LC_FILE_PRINT_PREVIEW` 在
  `common/lc_mainwindow.cpp:658-659` 被移出菜单。
- "链接了"与"用到了"是两件事。这不改变本节的许可结论，但它是打包清单里
  `ohos.permission.PRINT` 的来源之一——权限侧处置建议见 `权限说明.md` §4。

## 4. 许可兼容性说明

### 4.1 LDraw CC BY 4.0——**不能**简单写成"可直接随包分发"

CC BY 4.0 允许商业使用与再分发，只需署名；五项署名义务见
`docs/library/D2_精简零件库与资源部署方案.md` §5.2。但"许可允许分发"与"本次分发已经合规"
是两件事，以下三点使后者的证据不成立：

1. **逐文件许可少覆盖一个文件。** 带 `!LICENSE` 头的文件是 2740 个；
   `ldraw/ldconfig.ldr` 在 `manifest.json` 里的 `license` 字段是**空字符串**，文件本身也没有
   `!LICENSE` 行（实测解压核对）。它的再分发依据目前没有任何书面记录。
2. **许可文本指向的 CAreadme.txt 两边都没有。** 零件文件头写的是
   `0 !LICENSE Licensed under CC BY 4.0 : see CAreadme.txt`，但工作区里
   **没有 CAreadme.txt 的独立副本**（全仓 glob 无结果），`library-lite.zip` 的 2741 个条目里
   也**没有任何** readme/license/copying/credits 条目（实测解压核对）。被引用的文本既不在仓库、
   也不在包里。
3. **署名文本不随档案走。** 五项义务目前只落在仓库文档（`manifest.json` 与 D2 §5.2）。
   用户拿到的是 HAP，不是 GitHub 仓库；包内是否带这些文字见 §6。

**结论：CC BY 4.0 的"许可名称 + 许可 URL + 创作者可追溯"三项在包内没有落地证据。**
本项按**阻断项**登记于 §5.5，不得写成"可直接随包分发"。

### 4.2 LeoCAD GPL-2.0

要求：提供许可证全文、保留版权声明、提供修改版对应源码。
落实方式（**均指仓库侧，包内落地见 §6**）：
- 许可证全文 → 仓库根 `COPYING`（GPLv2 正文）
- 修改版源码 → 见 `docs/release/源码获取说明.md`
- 鸿蒙改动的说明 → 提交记录（`patches/` 目前只有目录约定，见 `源码获取说明.md` §6）

### 5.1 Qt 授权与 LeoCAD GPLv2 的兼容性 —— **BLOCKING，未闭环**

| 事实 | 依据 |
|---|---|
| LeoCAD 声明为 GPL **第 2 版**，无 "or later" 字样 | `COPYING` 为 GPLv2 正文；`README.md:91` 写 "GNU General Public License version 2"；`docs/README.md:4` 写 "GNU Public License v2" |
| Qt 6 开源授权为 **LGPL-3.0 / GPL-3.0** | Qt 官方授权页 |
| GPLv2-only 与 GPLv3 系**不兼容** | GNU 官方明确区分 GPLv2-only 与 GPLv2-or-later |

**治理原则（来自 `docs/ui/D1_界面清点与首发范围原则.md` §5.3，本文件服从该裁定）：**

> 在获得上游版权方明确书面确认之前，**一律按 GPLv2-only 的风险处理**。
> 不把 "version 2" 单方面解释为 "version 2 or later"；不在缺少授权依据的情况下，
> 靠项目声明"补充"成 or later。是否升版由**版权持有者**决定，不是使用方的解释空间。

两处必须说清楚的文本位置，避免再次误读：

- **`COPYING:242-248` 是版本选择条件原文**："If the Program specifies a version number …
  and 'any later version', you have the option of following …"。LeoCAD 的声明没有写
  "any later version"，因此这一条**不适用**，不能据此推出 or later。
- **`COPYING:282-299` 是 GPL 附录给新程序的样板通知**（"either version 2 of the License, or
  (at your option) any later version"）。那是模板示范文字，**不是本项目的授权声明**。
  此前草案把它当作 or later 的依据，是误读，已删除。

**待法务裁定的方案（D1 §5.3 (a) 原文，三选一，本文件不预设倾向）：**

| 方案 | 说明 | 代价 |
|---|---|---|
| Qt 商业许可 | 取得 Qt 商业授权后按商业条款分发 | 成本 |
| 上游重新授权 | 联系 LeoCAD 版权方取得 GPLv2-or-later 或例外许可的书面确认 | 时间、结果不确定 |
| 其他合规方案 | 由法务评估（如分离进程、放弃 Qt 等） | 待评估 |

**影响**：直接决定商店文案的许可表述与上传时的许可证字段。**闭环前不应提交审核。**

> 本文件中此前的两条"候选路径"（把 "version 2" 读作 "or later" 并补写声明 /
> 自行调整项目许可声明）均属 D1 §5.3 明确禁止的做法，**已删除，不再作为选项出现**。

## 6. 包内呈现现状（仓库材料 ≠ 包内材料）

**结论：截至本稿，仓库里具备的材料，在包内几乎都看不见。** 证据如下。

| 材料 | 仓库中存在 | 是否在包内 | 证据 |
|---|---|---|---|
| GPLv2 全文 `COPYING` | 是（`COPYING`，339 行） | **否** | `leocad.qrc` 未嵌入；CMake 生成的资源只来自 `leocad.qrc` 与 `resources/stylesheet/stylesheet.qrc`（`CMakeLists.txt:32-59`）；`leocad.pro:123` 的 `docs.files` 只服务 unix/qmake 的 `/usr/share/doc` 安装，鸿蒙构建不走该路径 |
| 版权声明 `COPYING.txt` / `CREDITS.txt` | 是（`docs/`，338 / 21 行） | **否** | 同上，未被任何 `.qrc` 引用 |
| 第三方组件清单、源码获取说明 | 是（`docs/release/`） | **否** | 同上 |
| LDraw 署名与许可文字 | 是（`manifest.json`、D2 §5.2） | **否** | `library-lite.zip` 的 2741 个条目中无 readme/license/copying/credits 条目（实测解压核对） |
| "关于"对话框 | 存在（`common/lc_aboutdialog.ui`、`common/lc_aboutdialog.cpp`） | 是 | 内容为：标题、版本号、一句简介、上游网站 `https://www.leocad.org`（纯文本，不可点击）、系统信息与 Qt/OpenGL/缓冲区信息（`:15-48`）。**没有**许可全文、版权声明、第三方清单，也没有本移植版的源码仓库地址 |
| `minifig.ini` | 是 | **是** | `leocad.qrc:133` |
| 精简零件库档案 | 是 | **是** | `leocad.qrc:124`（`assets/ldraw-lite/library-lite.zip`） |

由此可推出两条硬结论：

1. **当前包里没有任何一处向用户展示 GPLv2 全文、版权声明或源码获取方式。**
   "仓库里有 `COPYING`"不满足 GPLv2 §3 的随二进制提供义务，除非发行包本身附带。
2. **"关于"页目前不能承担这个角色**：它显示的是上游网站，不是本移植版源码地址；
   且帮助菜单里能打开外部 URL 的入口已被移除（`common/lc_mainwindow.cpp:738-745`，
   `LC_HELP_HOMEPAGE`/`LC_HELP_BUG_REPORT`）。把源码地址做成可点击链接会重新引入打开浏览器的动作，
   与离线承诺冲突；当前决定是**以纯文本呈现、不做链接**（由另一名成员在本轮修改 
   `common/lc_aboutdialog.ui` 中把锚点改为纯文本，落地后需在真机验收）。
   纯文本地址只满足"可见"，能否选择复制需真机确认。

**待办（组长负责，BLOCKING）**：确定包内呈现载体（"关于"页文本 / 随包文本文件 / 二者），
并出包验收。验收标准是可从 HAP 本身读到：许可名称与版本、许可全文、版权声明、
第三方清单、源码获取地址。**五项缺一不可。**

## 8. 维护要求

1. 新增任何第三方代码或资源前，先在本文件登记版本、许可、来源。
2. 每次升级 Qt、LDraw 库或 zlib，同步更新本文件与 `toolchain.lock`。
3. **零件库许可行目前没有自动化校验。** 上游 LeoCAD 有逐文件校验许可的脚本，本移植版未接入；
   首发零件子集（实际 **1160 个零件**）的许可登记由 `docs/library/D2_精简零件库与资源部署方案.md`
   与 `docs/library/D2_零件清单.csv` 人工核对。`scripts/library/check_qrc_resources.py`
   只校验 `.qrc` 引用的文件是否存在，与许可无关。
4. **零件库重建脚本不存在。** `manifest.json` 的 `generator.script` 指向
   `scripts/library/build_library.py`，但该脚本以及 `generate_selection.py`、
   `verify_library.py` **在仓库中均不存在**（全仓 glob 核实）。因此"从官方库重建档案"
   目前无法复现，只能分发现成档案，摘要校验靠
   `scripts/library/test_packaged_resources.py` 完成。补齐前不得对外承诺可重建。

   第 3、4 条都是已知缺口：若后续扩大零件库或改为自动同步上游，需要先补上逐文件许可校验与
   可复现的重建路径，否则不可分发内容可能静默进入发布包。

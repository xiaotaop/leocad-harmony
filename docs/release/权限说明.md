# 权限说明

> 负责人：成员 C　配套：`docs/release/隐私政策.md`
> 目标：**只申请必要权限，不申请网络权限**

## 1. 结论

| 能力 / 权限 | 是否申请 | 依据 |
|---|---|---|
| `ohos.permission.INTERNET` | **不申请** | 首发版全部功能离线可用；联网入口（Blender 附加组件、BrickLink 库存下载）已被 `ApplyFirstReleaseScope()` 从菜单移除 |
| 文件选择（系统 Picker） | 使用，非敏感权限 | 打开/保存模型必需 |
| 读取用户选择的文件 | 使用（仅限用户选择结果） | 打开 `.ldr` / `.mpd` |
| 写入用户选择的位置 | 使用（仅限用户选择结果） | 保存模型 |
| 应用沙箱内读写 | 使用（应用自有目录，无需额外权限） | 设置、缓存、零件库 |
| 位置 / 相机 / 麦克风 / 通讯录 / 相册 / 日历 / 短信 | **不申请** | 与功能无关 |
| 后台运行 | **不申请** | 前台建模工具 |
| 开机自启 | **不申请** | — |

> **结论的时效性：** 「不申请网络权限」是当前功能裁剪的结果。上游代码含 `common/lc_http.cpp`
> （Qt Network），若后续版本恢复上述联网入口，必须同时重新申请并复审隐私政策第 1 节，
> 不能沿用本文档的结论。

## 2. 逐项说明

### 2.1 文件选择

- **何时触发**：用户主动点击"文件 → 打开""文件 → 保存""文件 → 另存为"。
- **做什么**：调用系统文件选择器，由系统 UI 让用户选定文件；应用只拿到用户
  明确选择的那个路径。
- **不做什么**：不遍历目录、不扫描存储、不在后台访问文件、不读取用户未选择的文件。
- **取消行为**：用户取消选择时，应用保持当前模型不变，不报错。
- **分工文档依据**：§8「文件选择 → 模型层：平台层返回可读/可写的本地路径或明确的
  取消/失败状态」。

### 2.2 应用沙箱目录

应用在系统分配的沙箱内使用三个目录，不需要任何权限：

| 目录 | 内容 | 清理方式 |
|---|---|---|
| 应用数据目录 | 偏好设置、零件库副本 | 清除应用数据 |
| 应用缓存目录 | 零件索引缓存 | 系统可回收，应用可重建 |
| 临时目录 | 保存时的临时文件 | 保存成功后替换，失败则清理 |

`lcPiecesLibrary::FindBundledLibraryArchive()` 优先使用应用数据目录中的
`ldraw-lite/library-lite.zip`；该副本由平台层在首次运行时展开。

### 2.3 网络：明确不申请

首发版无联网功能，因此**不在 `module.json5` 中声明 INTERNET 权限**。
这样即使用户设备无网络，也不会出现任何联网相关错误提示。

构建层已确认（此前本节写作"需组长确认"，核查实际 CMake 配置后更正）：鸿蒙构建走根
`CMakeLists.txt`，第 75–82 行对 `leocad` 目标**无条件**定义 `LC_DISABLE_UPDATE_CHECK=1`，
`if(OHOS)` 内另加 `LC_DISABLE_NETWORK=1`。`scripts/build-harmony-app.ps1` 配置的正是这套
CMake 工程，`qtmain.cpp` 的启动更新检查分支因此不参与编译。

**仍需组长确认的是清单本身**：`module.json5` 是否真的未声明 `ohos.permission.INTERNET`。
这是打包产物的属性，源码宏不能替代检查。

**`LC_DISABLE_NETWORK` 覆盖不到的一类：外部网址。** 该宏只把 `lc_http` 换成空实现，不拦截
`QDesktopServices::openUrl`。帮助菜单的「主页」「报告问题」正是这样打开 `https://www.leocad.org/`
与 GitHub issues 的——应用自身不发请求，但会拉起浏览器联网，与本文档和隐私政策的离线承诺冲突。
D8 界面冻结时发现这两项此前无任何拦截，现已从菜单移除（列入 `ApplyFirstReleaseScope()`），
并由静态检查与窗口级菜单测试锁定。**没有网络权限不等于没有任何联网动作**，这两层要分别核对。

## 3. 风险与必须上报的事项

### 3.1 【已关闭】启动更新检查已被编译关闭

初稿按 `leocad.pro` 判断「宏只在 macOS 定义、鸿蒙可能联网」，定为 P0 上报。**核对实际构建系统后
该结论不成立**，此处更正：

| 事实 | 位置 |
|---|---|
| 启动时调用 `lcDoInitialUpdateCheck()`，受 `#if !LC_DISABLE_UPDATE_CHECK` 包裹 | `qt/qtmain.cpp:308` |
| 该函数请求 `https://www.leocad.org/updates.txt` | `common/lc_updatedialog.cpp:42` |
| 鸿蒙构建用根 CMake 工程，**无条件**定义 `LC_DISABLE_UPDATE_CHECK=1` | `CMakeLists.txt:75–82` |
| OHOS 另定义 `LC_DISABLE_NETWORK=1`（编译关闭网络层） | `CMakeLists.txt:81–83` |
| 构建脚本配置的就是这个工程 | `scripts/build-harmony-app.ps1:38`（`qt-cmake -S $repositoryRoot`） |
| 本机既有 Harmony 构建的 `qtmain.cpp` 编译命令含上述两个定义 | 编译命令实证 |

`leocad.pro:166` 的 `macx` 段定义是**历史 qmake 路径**，与鸿蒙构建无关——先前把它当作鸿蒙的
唯一保护来推断，是读错了构建系统。结论：**自动更新检查不进入鸿蒙二进制**，该 P0 关闭。

**由此仍待核对的不同事项（不是 P0，是要在真机/产物上验证的验收项）：**

1. 打包后的 `module.json5` 是否未声明 `ohos.permission.INTERNET`——清单属性，源码宏无法替代。
2. 真机首次启动（全新安装、清数据）抓 hilog，搜索 `leocad.org` / `updates.txt`，应无请求。

**回归保护**：`scripts/library/test_network_scope.py` 解析根 CMakeLists 的
`target_compile_definitions`，删除 `LC_DISABLE_UPDATE_CHECK=1` 或 OHOS 下的
`LC_DISABLE_NETWORK=1` 都会使其失败（已做移除定义的负向验证）。

## 4. 与隐私政策的一致性核对

| 隐私政策声明 | 代码/配置依据 | 一致 |
|---|---|---|
| 不联网 | 不申请 INTERNET（待查打包清单）；`LC_DISABLE_UPDATE_CHECK=1` 与 OHOS 下 `LC_DISABLE_NETWORK=1` 已由根 CMake 定义并经编译命令实证 | 代码侧一致；清单待核 |
| 无遥测/统计 | 无相关 SDK，`grep` 无分析代码 | 一致 |
| 不上传模型 | 无上传路径 | 一致 |
| 仅读写用户选择的文件 | `QFileDialog` 路径，无目录扫描 | 一致 |
| 数据仅在本地 | 沙箱目录 | 一致 |

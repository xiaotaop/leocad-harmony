## 5. 必须上报组长的阻断项

### 5.1 【已关闭】更新检查在鸿蒙构建下已编译关闭

**初稿结论有误，此处按实际构建配置更正。** 本节此前按 `leocad.pro` 推断「宏只在 macOS 定义、
鸿蒙可能未关自动更新、仓库无法核实」，据此定为 P0。核对实际的 CMake 构建后，这个结论不成立。

| 项 | 内容 |
|---|---|
| 实际构建入口 | `scripts/build-harmony-app.ps1` 用 `qt-cmake -S <仓库根>` 配置**根 CMake 工程**并产出 HAP，不走 `leocad.pro`。`leocad.pro` 是历史路径，不是鸿蒙构建路径 |
| 实际定义 | 根 `CMakeLists.txt:75–82` 对 `leocad` 目标**无条件**定义 `LC_DISABLE_UPDATE_CHECK=1`、`LC_DISABLE_RENDER_DIALOG=1`、`LC_DISABLE_BLENDER=1`；`if(OHOS)` 块内另加 `LC_DISABLE_NETWORK=1`、`LC_DISABLE_NON_CORE_FORMATS=1` |
| 编译证据 | 本机既有 Harmony 构建的 `qtmain.cpp` 编译命令包含 `LC_DISABLE_UPDATE_CHECK=1` 与 `LC_DISABLE_NETWORK=1`，即 `qtmain.cpp:308` 的 `#if !LC_DISABLE_UPDATE_CHECK` 分支在鸿蒙构建中**不参与编译** |
| 结论 | **自动更新检查在鸿蒙构建中已被编译关闭**，不会在首次启动访问 `leocad.org`。此前"宏只在 macOS 定义"的说法只对 qmake 路径成立，与鸿蒙实际构建无关 |
| 状态 | 该 P0 关闭。原判断基于读错构建系统，不是产品缺陷 |

**仍然成立、但性质不同的部分：网络权限清单需独立核对。**
「自动更新已关闭」只说明应用没有主动请求更新，**不等于**「全部离线声明已验收」：

- 隐私政策声称「不申请网络权限」，这是**包清单**层面的断言（`module.json5` 里有无 `ohos.permission.INTERNET`），
  与源码里的宏无关，必须查打包产物，不能由本节推断。
- `LC_DISABLE_NETWORK=1` 在 OHOS 下编译关闭网络层，是**双保险**（与 `ApplyFirstReleaseScope()`
  的菜单裁剪并存）；两者都成立才谈得上"离线"。
- 因此本节的验收项从「确认是否已传宏」改为「确认 HAP 清单未申请 INTERNET 权限 + 首次启动 hilog
  无 `leocad.org` 请求」，仍由组长在真机确认。

| 验证方法 | 真机首次启动（全新安装、清除数据）后抓 hilog，搜索 `leocad.org` / `updates.txt`：应无任何请求。同时解包 HAP 检查 `module.json5` 的 `requestPermissions` |
| 回归保护 | `scripts/library/test_network_scope.py` 现在解析根 CMakeLists 的 `target_compile_definitions`：删除 `LC_DISABLE_UPDATE_CHECK=1` 或 OHOS 下的 `LC_DISABLE_NETWORK=1` 都会使该测试失败（已做移除定义的负向验证） |

> 教训记在这里：审查构建约束要读**实际被调用的构建系统**，`leocad.pro` 与 `CMakeLists.txt` 在本仓库
> 并存且宏定义条件不同，只读其中一个会得出相反结论。

## 7. 已知的环境约束（开发期）

| 项 | 说明 |
|---|---|
| 本机无 Qt / cmake / uic / moc / rcc | 已用 `scripts/dev/install-qt-desktop.sh` 装到 `.devtools/`（不入库） |
| 本机内存 7 GB | 并行编译需限制任务数；`build-desktop.sh` 默认 `JOBS=4`，32 并发会触发换页导致编译器长时间无响应 |
| WSLg 截屏受限 | `xwd -root` 对 WSLg 根窗口报 `BadMatch`；界面验证以启动稳定性 + 离屏渲染为主 |
| `libGL.so` 需手工补链 | `libgl-dev` 只装符号链接，目标库不在 sysroot；安装脚本已自动修复 |

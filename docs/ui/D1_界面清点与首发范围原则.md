## 3. 精简菜单原则

### 3.1 判定规则（按优先级）

1. **核心闭环优先**：§1.1 列出的 7 步用户闭环涉及的入口必须保留。
2. **按 §1.2 负面清单剔除**，不做"看起来有用就留"的判断。
3. **保留入口但不保留实现**：菜单项移除，但 action 对象与 dock 指针不得置空。
   原因：`UpdateDockWidgetActions()` 无条件解引用 5 个 dock 指针，
   置空会在"视图 → 工具栏"时崩溃。
4. **集中控制**：所有移除集中在一个函数，便于评审与整体回退。
5. **不改 `.ui` 结构**：偏好设置裁剪用隐藏控件实现，保持 `.ui` 与上游一致，
   避免删除控件带来的 `<tabstop>` 与 `ui->` 引用同步风险。

### 3.2 移除清单（按 §1.2）

| 类别 | 命令 |

## 4. 精简零件库筛选原则（500–1500 件）

### 4.1 为什么不能按 `!CATEGORY` 元数据选

基线 `resources/library.zip` 只有 **128 个**顶层零件，远低于要求。
补全时若按官方库的 `!CATEGORY` 字段筛选会遇到两个问题：

- 该字段很稀疏：24985 个官方顶层零件中仅 6470 个带 `!CATEGORY`；
- 分布失衡：带该字段的零件里 `Plate` 仅 28 个，而分类树需要覆盖主要类别。

### 4.2 采用的原则

1. **按 LeoCAD 自身分类表达式筛选**。单一事实来源是
   `common/lc_category.cpp` 的 `DefaultCategories[]`（31 条表达式），
   用与 `lcMatchCategory()` 等价的分支语义（`^` 整词、`%` 描述开头、`|`/`&`/`!`）匹配零件描述。
   这样"选进库的零件"与"分类树能显示的零件"不会脱节。
2. **只收纯色建筑件**：排除图案件（描述以 `~` 开头）、别名（`=`）、
   Sticker、Obsolete、Moved。因此不需要 `parts/textures/`。
3. **每类设预算上限**，大分类多给，保证 31 个分类不出现大面积空白。
4. **依赖闭包**：从种子递归解析 `1 <color> … <file>` 引用，纳入子件与图元；
   闭包超上限即失败退出，不静默截断——否则用户会看到缺件的模型。
5. **数量硬约束**：500 ≤ 顶层零件数 ≤ 1500，超出即构建失败。
6. **许可白名单**：只接受 CC BY 4.0 / CC BY 2.0+4.0 / 旧 CCAL 2.0 三种 `!LICENSE`，
   出现其他即失败。
7. **可复现**：zip 条目排序、时间戳固定、压缩级别固定，两次构建字节一致。

### 4.3 打包格式约束（由加载器决定，不可自由选择）

| 约束 | 原因 |
|---|---|
| 根目录必须 `ldraw/` | `lcPiecesLibrary::OpenArchive()` 对 `LDRAW/` 前缀做 `memcmp` |
| 零件 `parts/`、子件 `parts/s/`、图元 `p/` | 名称大写化后按目录前缀分流 |
| 必须含 `ldraw/ldconfig.ldr` | `LoadColors()` 优先从包内取色，缺失会静默回落内置色表 |
| 文件名大小写不敏感唯一 | 加载器统一转大写后放入 `std::map` |

### 5.2 LDraw CC BY 4.0 的五项署名义务

1. 指明创作者 → 逐文件 `0 Author:` 头，需进 manifest
2. 提供作品 URL → `https://library.ldraw.org/`
3. 指明许可名称 → `CC BY 4.0`
4. 提供许可 URL → `https://creativecommons.org/licenses/by/4.0/`
5. 说明是否修改 → 是：重新打包为子集，零件内容未改

### 5.3 D1 必须上报的两个开放项

**（a）Qt 授权与 LeoCAD GPLv2 的兼容性**

| 事实 | 依据 |
|---|---|
| LeoCAD 声明为 GPL **第 2 版** | `COPYING` 为 GPLv2 正文；`README.md` 写 "version 2" |
| Qt 6 开源授权为 LGPL-3.0 / GPL-3.0 | Qt 官方授权页 |
| GPLv2 与 GPLv3 系**不互相兼容** | 标准许可条款 |

两条候选路径（**不自行下结论**）：
- 若 "version 2" 可读作 "or later"，则可与 GPLv3 系组合，
  需在项目声明中明确"或更高版本"；
- 若确定为 GPLv2-only，则不能分发链接 LGPLv3 的二进制，需换 Qt 版本或分发方式。

**影响**：决定商店文案许可字段与上传时的许可声明，需在 D11 前闭环。

**（b）应用市场对 GPL 类应用的政策**：是否接受、是否要求额外源码获取声明。

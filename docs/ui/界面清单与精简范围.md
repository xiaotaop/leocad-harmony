# 界面清单与首发精简范围

> 负责人：成员 C　依据：`docs/LeoCAD_鸿蒙PC首发版_两周分工与技术方案.md` §1.2、§3.1
> 状态：已实现并桌面验证（`common/lc_mainwindow.cpp` 的 `ApplyFirstReleaseScope()`）

## 1. 精简机制

所有"首版不做"的入口集中在一个函数里移除：

```cpp
void lcMainWindow::ApplyFirstReleaseScope();   // common/lc_mainwindow.cpp
```

由 `CreateMenus()` 末尾调用。三条设计约束：

1. **只从菜单/工具栏移除 `QAction*`，不删除对象、不置空 dock 指针。**
   `UpdateDockWidgetActions()` 会无条件解引用 `mPartsToolBar`、`mColorsToolBar`、
   `mPropertiesToolBar`、`mTimelineToolBar`、`mPreviewToolBar`；把某个 dock 指针置空，
   下次打开"视图 → 工具栏"就会崩溃。
2. **整体可回退。** 不调用该函数即恢复上游行为；这也是 PR 里的降级方案。
3. **移除后清理悬空分隔符**，避免菜单末尾出现孤立横线。

`tests/library/test_ui_scope.py` 静态锁定上述三条（含"不得置空指针""必须覆盖每个禁用命令"）。

## 3. 偏好设置裁剪

实现：`qt/lc_qpreferencesdialog.cpp` 构造函数的 `RemovedPreferenceWidgets[]` 数组，
对控件调用 `hide()`。**不改 `.ui`**，理由有三：

1. `.ui` 与上游保持一致，合并上游更新时不会冲突；
2. 一个数组即可整体回退，删掉即可恢复完整偏好设置；
3. 删除控件需同步清理 `<tabstop>` 与 `.cpp` 中的 `ui->` 引用，隐藏不会引入这类风险。

`QFormLayout` 中隐藏字段会留下孤立标签，因此每个字段的 `QLabel`（`label_5`、
`label_9`、`label_10`、`label_17`、`label_18`、`label_39`）一并隐藏。

**注意**：该目录属共享热点，改动必须以小型 PR 提交并由组长复核（分工文档 §3.1）。
`tests/library/test_ui_scope.py::PreferencesTrimTests` 锁定每个必须隐藏的控件，
并且直接断言 `RemovedPreferenceWidgets[]` 数组内容（而非整个构造函数），
避免"控件在别处被引用"造成的假通过。

| 页 | 保留 | 隐藏／移除 | 理由 |
|---|---|---|---|
| 常规 | 语言、主题、默认作者名、固定方向键 | 检查更新、零件库路径浏览、零件库压缩包浏览、颜色配置浏览、人仔设置浏览、POV-Ray 可执行文件、LGEO 路径 | 库固定随包、不联网、不做外部渲染 |
| 渲染 | 着色模式、抗锯齿、凸点样式、边线、网格、淡化上一步颜色 | Blender 插件设置按钮 | Blender 不在范围 |
| 快捷键 | 键盘、鼠标 | — | 物理键盘属核心操作 |
| 分类 | 全部分类编辑 | — | 用户可自定义分类 |

实现状态：已隐藏（`RemovedPreferenceWidgets[]`，19 个控件 + 6 个标签）。
验证：`tests/library/test_ui_scope.py::PreferencesTrimTests`（5 项）。

语言下拉保留 8 项（含"简体中文"），`gLanguageLocales` 不动。

## 3.1 零件面板空态

三种"列表是空的"情形必须区分文案，否则用户无法判断是功能缺失还是操作问题：

| 情形 | 文案 |
|---|---|
| 库未加载 | 未找到零件库。请重新安装应用，或检查应用数据目录。 |
| 当前分类无零件 | 此分类下没有可用零件。 |
| 搜索无匹配 | 没有匹配的零件，请尝试其它关键词。 |

实现要点（`lc_partselectionwidget.cpp`）：

- 空态标签是 `mPartsWidget->viewport()` 的子控件，作为**覆盖层**显示。
  不能加进面板的垂直布局——那会挤压列表且列表仍在下方可见；
  也不能 parent 到 `QListView` 本身——`QListView` 继承 `QAbstractScrollArea`，
  非 viewport 子控件会绘制在滚动内容区之外，盖不住行。
- 几何在 `resizeEvent` 与 `UpdateEmptyState()` 中同步到 `viewport()->rect()`。
- 有零件可见时 `hide()`，避免吞掉行点击。

验证：`tests/library/test_ui_scope.py::EmptyStateOverlayTests`（6 项，
两个布局缺陷各自都能被测试捕获）。

## 4. 窗口尺寸

`CreateWidgets()` 原来直接 `restoreGeometry()`。若上次保存的几何来自另一套屏幕
（例如外接显示器已断开），窗口会恢复到屏幕外，表现为"启动后什么都没有"。现在的处理：

1. 恢复几何后检查是否与任一 `QGuiApplication::screens()` 的 `availableGeometry()` 相交；
2. 不相交则回落 800×600 并居中到主屏可用区域。

## 6. 降级与回退

| 场景 | 动作 |
|---|---|
| 精简导致某核心操作不可达 | 从 `RemovedCommands[]` 中删掉对应条目，重新构建即可，无需改其他代码 |
| 需要临时恢复完整 UI 做对照 | 注释掉 `CreateMenus()` 末尾的 `ApplyFirstReleaseScope();` |
| `.ui` 删控件引起编译失败 | 按 `test_removed_ui_widgets_have_no_cpp_references` 的提示同步清理 `.cpp` 与 `<tabstop>` |
